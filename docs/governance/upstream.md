## 更新流程

上游同步独立处理，避免混入普通功能提交：

1. 在干净工作区获取上游，比较版本差异及来源。
2. 从 `dev` 建立有隔离价值的维护分支，记录要导入的准确提交。
3. 普通 merge 导入上游，解决冲突；特别检查 CI、发布、统计、上传默认值和许可是否被重新带回。
4. 完成 Web 基线，核心复制 / 存储变化补真实验收；PR 合入 `dev`。
5. 在本文件追加同步记录，阶段稳定后遵守 `dev -> main` 流程。

首次导入之后的上游提交若不符合本项目提交标题规则，维护 PR 可经审核提供精确上游 SHA；检查器仅豁免可证明属于该 upstream 提交祖先链的导入提交，不豁免本地新提交。常规 CI 默认不联网获取 upstream，也不默认启用这一豁免。
