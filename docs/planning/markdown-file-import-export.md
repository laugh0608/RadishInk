# Markdown 文件导入导出

状态：Web 单文件闭环已在 `4343524` 实现，验证与未验证项见 [实现记录](../records/2026-10-06-markdown-file-import-export.md)。2026-10-07 新增文件菜单与文章 ZIP 规划，尚未实施。下文前半部分记录当前单文件行为，[下一阶段](#下一阶段文章包与文件菜单) 记录目标差异；优先级见 [当前状态](../status/current.md)。

## 已实现的目标与范围

完成“导入本地文件为新文章 → 编辑 → 导出最新内容 → 重新导入”的文本交换闭环，不依赖账号、云服务、插件或目录授权。不把普通 `.md` 称为完整备份，不扩展桌面客户端、服务端、批量、拖拽或附件打包。

## 首轮交互契约

| 项目     | 实际行为                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------- |
| 入口     | Web 文件栏的新建按钮下方提供“导入 Markdown”和“导出”；触屏移动布局从底部“更多功能”进入                     |
| 文件选择 | 单文件 `.md` / `.markdown`，扩展名不区分大小写；取消不改变文章，输入重置后可再次选择同一文件              |
| 限制     | 最大 5 MiB（5 × 1024 × 1024 字节），读取前后校验；空文件可导入；严格 UTF-8，接受 BOM，不猜测 GBK / UTF-16 |
| 文本规范 | 导入去掉 UTF-8 BOM，CRLF / CR 统一为 LF；拒绝 NUL、DEL 和除 TAB / CR / LF 外的 C0 控制字符                |
| 目标位置 | 浏览器存储创建独立历史文章；目录模式始终导入当前工作区根目录，不切换存储模式，不覆盖当前文章              |
| 标题     | 支持的顶层标量 `title` 优先，否则使用去扩展名的源文件名；空标题回退“未命名文章”                           |
| 文件名   | 复用 `normalizeMarkdownFileName`，清理路径分隔符、非法字符、控制字符和首尾点；限制 60 字符，统一 `.md`    |
| 同名     | 浏览器历史标题和目录文件名分别递增 ` (1)`、` (2)`；目录中的文章标题仍保留原标题                           |
| 数量     | 浏览器原有 30 篇历史上限不变；导入时达到上限明确拒绝，避免导入淘汰旧稿                                    |
| 导出     | 点击时同步取得正文、文章标题、主题与原元数据的快照；包含尚未自动保存的修改，不读取旧磁盘内容              |
| 下载     | UTF-8、LF、无 BOM，不强制增删正文结尾换行；提示“已发起下载”，不声称文件已落盘；对象 URL 延迟 60 秒释放    |

## 元数据与资源

复用 `markdownFileMeta`，不引入另一套 YAML 序列化或存储 schema。原始 frontmatter 中的未知字段、嵌套结构、注释和顺序保留；仅更新受支持的顶层 `title`、`theme`、`themeName`。修正旧工具将嵌套字段误认为顶层字段的问题。

该工具仍是有限标量解析器，不是通用 YAML 编辑器：支持普通文本及引号标量；应用字段若使用块标量、对象、数组、锚点或标签等复杂值，则原样保留，不拆改子节点。复杂 `title` 无法用作标题时使用文件名，界面标题或导出文件名可能与这类外部 YAML 值不同。原文不含 frontmatter 时增加应用元数据块；不完整的块作为正文保留。闭合分隔符后至多消费一个空行作为分隔，并在序列化时恢复；正文自身的额外空行、缩进代码及尾部空白保留。

文件中的主题若未安装，打开时使用默认主题并给出提示；后续保存 / 导出使用当前编辑器主题。文件不携带自定义 CSS 或主题资源。标题与主题不是凭据，导出不包含图床、AI 或存储设置。

图片、公式、Mermaid、链接、HTML 和扩展 Markdown 均保留为源文本。普通文件只携带文本，图片及附件不打包、不自动上传、不下载归档、不重写路径。入口持续提示相对路径可能无法显示；浏览器对象 URL 也不是可移植资产。预览依然可能读取文章中的图片和字体，预览 / 两种复制沿用现有清理边界。

## 保存与状态一致性

实际 Web 有两条文章持久化路径，不能把默认文章写入无人展示的另一座数据库：

- 浏览器存储：复用 `historyStore` / `historyDb`。导入文章在已有 `markdown` 字段保存含 frontmatter 的完整源文，编辑器恢复正文；后续保存将最新正文合回原元数据。既有纯正文记录仍可读取，无字段、数据库版本、存储键或迁移变更。
- 目录模式：复用 `StorageAdapter`、`useActiveFilePersistence` 和文件列表转换。导出复用 `lastSavedContent` 中的原始元数据，正文从编辑器取得。

读取与校验成功后，先保存当前文章，再创建导入文章；不依赖可能尚未更新的 dirty 标志。历史事务真正提交后才更新列表，配额或写入错误向调用者传递。目录保存使用同一适配器的共享队列，避免 App 自动保存和侧栏操作交错覆盖；空正文也进入保存流程。历史列表更新不再用较早的保存结果回滚正在输入的内容。

打开文件选择器时绑定文章和工作区身份；在读取、保存、同名检查、写入和列表扫描的异步边界复核。工作区路径 / revision、存储适配器或目录 handle 变化均使旧操作失效。写入已开始的任务仍可能在原工作区完成，届时提示已写入但未打开，不能更新新工作区的编辑器或列表。目录适配器在每次调用开始时捕获实际根 handle，后续解析不会转到新目录。

旧稿保存期间继续编辑时，文件路径使用既有最多两次“保存最新内容”的机制；浏览器历史路径停止导入并要求稍后重试。新文章写入期间继续编辑时，仅加入列表，不自动打开。失败保留当前编辑器；目录底层创建 / 写入失败可能留下新建空文件或部分文件，用户源文件从不删除。不对其他页面或外部程序同时改写同一磁盘目录提供跨进程事务保证。

存储模式切换先初始化候选，再保存旧稿，成功后才释放旧适配器；取消、权限失败或旧稿保存失败保留原模式。文件选择器取消本身不触发旧稿保存。文章尚无可持久化身份时停止导入并提示先导出，避免覆盖未关联草稿。

### 文件菜单与格式

| 命令                    | 目标行为                                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| 导入 Markdown 为新文章… | 保留 `.md` / `.markdown`、5 MiB 与 UTF-8 规则；P2 后创建文章包；不覆盖当前文章，不自动读取源文件旁边的资源 |
| 导入文章包（.zip）…     | 补充建议：在 P2b 与 ZIP 导出一起完成，解包为新的文章及 `asset/`，原包和已有文章不动                        |
| 导出当前文章包（.zip）  | 用户要求的默认导出；包含点击时的最新 Markdown 与该文章的资源目录，下载名称明确为 `.zip`                    |
| 仅导出 Markdown（.md）  | 保留为次要入口，明确图片 / 附件不随行；失败抢救时仍可取得最新正文                                          |

菜单中的“导出为 Markdown”不能实际下载 ZIP 却隐瞒格式。P1 先迁移当前纯文本操作，P2b 完成后再调整默认导出；未实现的 ZIP 不提供假成功按钮。

建议输出 `<文章目录名>.zip`，内部是单个文章目录及 `index.md` + `asset/`，即使没有图片也包含空 `asset/`。文章正文、应用元数据和未知 frontmatter 保留；包内不带账号 ID、凭据、站点设置、历史库或自定义主题 CSS，不称为完整工作区备份。

### 导出快照与资源范围

开始导出时绑定文章、工作区 / 登录身份、正文、主题与资源版本；打包期间继续输入不改变这次快照。资源写入未完成时明确等待或取消，不能把占位、半张图片或旧 Markdown 打包。正文取编辑器最新值，仍不要求先成功自动保存到原目标。

默认打包该文章所属 `asset/` 中的全部受支持资源，包含尚未显式清理的未引用图片，避免只用正则扫描 Markdown 误删 HTML / 扩展语法引用；不扫描整个工作区，不带入其他文章或目录。导出前列出无法解析 / 读取的本地引用，保留外链但提示“外链仍需网络，未收录进包”。

资源缺失、权限撤回、网络或读盘失败时停止默认 ZIP 导出并说明原因，允许用户明确改用仅 Markdown；不能悄悄缺图后报告完整文章包。处理中切换工作区或账号时取消结果交付；同一文章资源发生变更时保留固定版本或中止重试，不能把两次版本拼成一个包。

浏览器使用可控内存的打包方式，并评估 Web Worker / 流式库的必要性；在引入 ZIP 依赖前核对浏览器兼容、许可、体积和安全维护。大文件操作提供进度、取消和资源释放；下载仍只报告“已发起”，不能证明设备已经保存。

### ZIP 导入与解包约束

建议首轮只支持本产品的单文章格式：一个顶层目录、恰好一个主 `.md` 文件及 `asset/` 内的受支持图片；不支持多篇批量包、加密包、嵌套压缩包、脚本或任意附件。是否兼容第三方常见目录结构，在后续真实需求中增加，不隐式选择第一个 Markdown。

解包前检查结构与声明大小，解压过程中继续限制实际字节、条目数和耗时。建议原型限额：压缩包 100 MiB、解压后 200 MiB、最多 500 条目、主 Markdown 仍为 5 MiB，资源遵循统一图片限额；这些数值待 P2 测量冻结，导出也校验同一回读能力，避免生成本应用不能重新导入的“标准文章包”。

拒绝绝对路径、盘符、NUL、父级穿越、规范化后重复路径、大小写 / Unicode 冲突、符号链接及其他特殊条目；校验规范化后的最终目标位于新文章目录，不能相信 ZIP 内原文件名。压缩炸弹、CRC 损坏、条目大小谎报和中途取消均不得留下看似成功的新文章。

先在隔离暂存位置验证完整包与资源，再保存当前稿并提交新文章；失败只清理由本次创建且可确认归属的暂存内容，已有文章和源 ZIP 保持原样。目录 IO 不具备天然跨文件事务，需要可恢复状态和重试策略。主题缺失、未知 frontmatter、同名消歧及继续输入 / 晚到结果沿用现有契约。

### 验收

- 两种现有存储交叉执行“Markdown 导入 → 粘贴图片 → 立即 ZIP 导出 → ZIP 导入 → 刷新”，逐字比较正文和元数据、逐字节比较资源；服务器模式接入后复用同组行为测试。
- 覆盖空资源目录、中文 / 空格文件名、同名、动图、透明图、未引用资源、外链、缺图、图片处理未完成、打包期间编辑及模式 / 账号切换。
- 对恶意 ZIP 路径、资源越界、压缩炸弹、超限、损坏、重复路径、存储部分失败和取消提供负向测试，确认不会覆盖旧稿或泄露其他文章。
- 真浏览器检查文件选择、下载、解压结构及再次导入；支持范围内的手机实测单列。ZIP 完成不等于公众号粘贴或整站备份恢复通过。
