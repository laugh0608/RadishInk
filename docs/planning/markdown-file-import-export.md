# Markdown 文件导入导出规划

状态：未来规划，尚未进入实现和验收。本文定义目标与建议的首轮范围，不表示界面已经提供这些功能；启用顺序以 [当前状态](../status/current.md) 为准。

## 目标与现有基础

让用户将本地 `.md` 文件带入浏览器编辑，并将当前文章导出为可在其他 Markdown 工具中继续编辑的文件。文件进出应能用于日常交换和单篇备份，不依赖账号、云服务或目录授权。

现有能力需要复用并区分：

- `apps/web/src/storage/StorageAdapter.ts` 及 IndexedDB / FileSystem 适配器处理工作区读写；目录工作区不是所有浏览器都可用的单文件导入入口。
- `apps/web/src/hooks/useFileSystem.ts` 与 `useActiveFilePersistence.ts` 已处理文章打开、保存及未保存内容；新增操作要沿用其状态和失败语义。
- `apps/web/src/utils/markdownFileMeta.ts` 已处理文章 frontmatter、标题与主题元数据；不能另建一套互不兼容的序列化规则。
- 现有“复制 HTML”“复制到公众号”输出排版结果；Markdown 导出应取文章源内容，不从渲染 HTML 反推。

## 建议的首轮范围

| 能力         | 建议行为                                                     | 边界                                           |
| ------------ | ------------------------------------------------------------ | ---------------------------------------------- |
| 单文件导入   | 用户选择 `.md` / `.markdown` 文件，校验后新建文章并打开      | 默认不覆盖当前文章，也不切换整个存储模式       |
| 单篇导出     | 将当前编辑器中的最新文章内容导出为 UTF-8 `.md` 文件          | 不依赖自动保存是否已经完成，不导出旧的磁盘快照 |
| 文件名与标题 | 沿用现有文件名规范，使用文章标题或源文件名作为默认名称       | 清理路径分隔符与非法名称；同名文件不静默覆盖   |
| 元数据       | 保留原有 frontmatter 和未知字段，复用已支持的标题 / 主题字段 | 不把设置、图床或 AI 凭据写入文章               |
| 失败与取消   | 取消后保持原状；读取、校验、持久化或下载准备失败时说明原因   | 不能在保存失败后切换文章并丢失原内容           |

导入按钮与导出按钮的位置在实施前结合现有文章列表和编辑器导航确定。首轮优先明确可发现的文件选择 / 下载入口；拖拽文件、批量导入与快捷键可以后续补充。

## 内容与资源契约

- 输入首先支持 UTF-8，包括带 BOM 的文件和常见 LF / CRLF 换行。编码错误、二进制内容和超过限制的文件须在替换编辑状态前被识别；首轮不静默猜测 GBK 等编码。
- 正文中的代码块、公式、Mermaid、链接、原生 HTML 和自定义 Markdown 语法保留为源文本。预览与复制继续使用现有 HTML 清理边界，导入内容不能绕过它。
- 原有 frontmatter 未知字段必须可往返；需要更新的应用字段、导出换行 / BOM 策略和无 frontmatter 的文章如何携带标题，在实施前以样例冻结。不得以重排 YAML 为由丢失无法识别的内容。
- 普通 `.md` 只携带文本。保留图片 / 链接引用，不自动下载、上传或嵌入远程资源；相对路径缺少资源根目录时，要让用户知道文件可能无法独立显示图片。
- 浏览器对象 URL 等临时资源不能被宣称为可移植资产。带附件的归档格式、路径重写和完整工作区备份属于后续范围。
- 选择文件是用户主动读取本地文件的动作；导入本身不发起网络请求。预览远程图片等行为仍沿用文章预览的现有边界。

## 职责与状态一致性

文件选择、读取与下载交互留在 `apps/web`；内容与元数据解析复用现有工具，工作区落盘通过现有存储适配器。只有出现真实的跨平台复用需求时才调整 `packages/core`，不提前引入新的文件服务层。

导入在读取和校验完成后才进入持久化及文章切换。当前文章未保存、写入配额不足、工作区权限被撤回、读取期间切换工作区等情况必须有明确处理，失败时保留当前文章和可恢复内容。单文件操作要绑定启动时的工作区身份，不能把迟到的结果写到另一个工作区。

导出在用户操作时取得一致的文章快照，包括尚未落盘的编辑与相应元数据。下载资源创建失败须可见；浏览器下载已发起与文件已实际落盘分别描述，不能伪造保存确认。临时对象 URL 在合适时机释放。

首轮不更改现有存储键、数据库 schema 或草稿默认来源。若实施中发现必须迁移，先补迁移、备份及恢复方案，再修改存储契约。

## 分阶段推进

1. 样例与交互确认：冻结文件大小限制、编码 / 换行策略、标题与 frontmatter 往返、同名处理、未保存内容和相对资源提示。
2. 单文件闭环：导入为新文章、编辑、导出、重新导入；覆盖浏览器默认存储及已有目录工作区，保留不支持目录 API 的浏览器路径。
3. 体验扩充：按真实需求补拖拽、多文件、冲突选择与批次失败结果。
4. 资源与备份：另行设计文章加附件的可移植归档，以及工作区备份 / 恢复；不把普通 `.md` 导出称为完整备份。

## 验证与交付条件

| 场景     | 必须证明的行为                                                                |
| -------- | ----------------------------------------------------------------------------- |
| 文本往返 | 中文、emoji、空文件、代码、公式、Mermaid、未知 frontmatter 字段不会无说明丢失 |
| 最新编辑 | 导出包含当前未保存修改，导入失败不会破坏当前文章                              |
| 文件边界 | 同名、非法名称、扩展名大小写、编码错误、超限与取消有确定结果                  |
| 存储失败 | IndexedDB 配额 / 写入失败、目录权限撤回、工作区切换不会伪造成功或错写         |
| 内容安全 | 合成活动 HTML 在预览及两种复制中不执行，源文本仍可导出                        |
| 浏览器   | 支持目录 API 和不支持该 API 的浏览器均完成单文件流程，移动端另列实际支持结果  |
| 外部请求 | 文件进出操作不隐式上传文章或资源；实际预览请求与导入操作分开记录              |

实施时遵循 [验证基线](../development/validation.md)。单元 / 集成测试覆盖状态与失败边界，浏览器验证真实文件选择、下载及重新导入；公众号粘贴验收仍是独立证据。该功能不依赖 [插件系统](plugin-system.md) 落地，也不提前把基础文件操作变成插件。
