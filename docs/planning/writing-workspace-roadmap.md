## 补充约定

- **“浏览器存储”比“浏览器缓存”更准确。** 数据仍在当前浏览器与站点源下，不是用户选定的磁盘目录，也不是云备份。三种模式共用文章逻辑结构，物理存放方式不同。
- **服务器存储不等于自动同步。** 首轮是主动选择工作区后保存到自托管服务器；不自动上传本地文章，不合并三个工作区，不承诺离线多端同步或多人协作。
- **补上 ZIP 重新导入。** 仅支持导出 ZIP 会形成单向备份；建议在 P2b 一起支持本产品生成的单文章 ZIP。批量文章包和完整站点备份不随之开放。
- **保留仅导出 Markdown。** 默认 ZIP 解决图片携带问题，纯文本入口继续用于外部编辑器和故障抢救，名称要明确区分。
- **资源和正文必须一起管理。** 重命名、复制、移动、删除、撤销和历史上限都会影响图片生命周期，不能只实现“写入图片文件”。
- **公众号图片单独验证。** 本地相对路径、临时对象 URL 和需登录的服务器图片都不能自动视为公众号可访问资源；不为解决转存问题恢复隐式图床上传。
- **现有数据兼容优先。** P1 不清除旧配置；P2 的存储升级、旧散落 `.md` 和既有外链图片有独立迁移策略，原件不自动移动或删除。
