# 编辑器界面与工具栏

状态：2026-10-07 规划，尚未实施。对应截图一、二、三，属于 [工作区计划](writing-workspace-roadmap.md) 的 P1；ZIP 实际行为在 P2b 接入。

## 移除图床与 AI

目标是 Web 当前产品不再提供这两类功能，不只是隐藏截图中的两个按钮。

- 从常规顶栏、自动隐藏后的浮动栏、紧凑菜单、编辑工具栏、选区 AI 改写、事件唤起和帮助说明中移除图床 / AI 入口及挂载。检查所有实际调用者，避免遗留不可见的设置弹窗和请求。
- 断开 Web 图片粘贴 / 选图对 `uploadEditorImage` 的调用，停用 AI 模型列表、连通性测试和生成操作；已有配置不得让功能重新启用。移除无调用者的 Web 专用实现与测试按实际依赖处理，不顺带裁剪桌面端、后端或升级依赖。
- 旧图床 / AI 的本地配置保留为未启用数据，不迁移、不发送、不自动清除；现有 Markdown 外链图片、正文和自定义主题继续可读。
- P1 到 P2 之间，图片文件粘贴明确说明“文章图片保存功能尚未提供”，保留原选区和正文，不插入上传占位、不要求配置图床；普通文本与 Markdown 图片链接仍可编辑。P2 接入“插入图片”并直接保存到当前文章资源目录。
- “移除图床”不等于所有请求归零：已有外链图片预览仍可能访问原地址。验收应区分预览资源请求与被停用的上传 / AI 请求。

现状入口：`Header.tsx` 同时包含顶栏和隐藏状态下的浮动栏；`Toolbar.tsx` / `ToolbarCompactMenu.tsx` 挂载 AI 按钮，`MarkdownEditor.tsx` 挂载选区改写和图片粘贴。实际实现需追踪这些调用关系，不能只删 JSX 文案。

## 顶栏“文件”菜单

桌面在截图二的右侧操作区、复制按钮左侧增加“文件”按钮，建议排列：

```text
[明暗主题] [文件 ▾] [复制 HTML] [复制到公众号] [收起顶栏]
```

P1 菜单复用现有单文件能力，先提供“导入 Markdown 为新文章…”和“导出当前文章为 Markdown（仅文本）”。P2b 完成后，主导出改为“导出当前文章包（.zip）”，纯 `.md` 导出保留为次要选项，另加入 ZIP 导入；格式、资源和错误约定只在 [文件进出契约](markdown-file-import-export.md#下一阶段文章包与文件菜单) 维护。

侧栏移除现有导入 / 导出按钮和常驻长说明，保留新建、搜索与文章列表。格式限制移到文件菜单的简短说明和实际错误提示；不要让实现细节长期占用写作区。

自动隐藏顶栏时，浮动栏仍提供文件菜单。移动端保留底部“更多功能”中的“文件”入口，复用同一命令和忙碌状态；不新增一套不同的导入逻辑。窄屏用点击可用的面板或子页，避免只能悬停打开多级菜单。

所有入口共用同一个进行中任务状态：阻止重复导入 / 导出，文章或工作区变化后迟到结果仍遵守现有归属检查。文件选择器应由用户点击直接触发；菜单卸载不得中止已经选择的文件处理。支持键盘打开、方向键导航、Esc 关闭与焦点返回，操作失败时保留可恢复的当前文章。

## 渐进收纳编辑工具

当前 `Toolbar.tsx` 按容器宽度 `< 680` 切换 `compact`，`Toolbar.css` 隐藏整个 `.toolbar-full-only`；截图三展示的是这套整体折叠行为。目标改为按真实可用宽度保留尽可能多的常用操作。

```text
宽： [更多 ⋯] [粗体] [斜体] [下划线] [删除线] [标题 ▾] [列表 ▾] [引用] [代码] …
窄： [更多 ⋯] [粗体] [斜体] [标题 ▾] …
```

- 有溢出时，“更多编辑工具”固定在横栏左侧，可放下的工具紧接其右；没有溢出时隐藏该按钮，全部工具直接展示。
- 建议收纳优先级：粗体 / 斜体、标题、列表、链接 / 图片、引用 / 代码、下划线 / 删除线、分隔线、Mermaid、发布偏好、语法帮助。具体以实际按钮尺寸和操作频率复核；主工具仍可有自身选项菜单。
- 只把本次放不下的工具放入“更多”，不重复所有操作。主栏和溢出菜单消费同一命令定义、选中与禁用状态；去除 AI 后不保留空分隔组。
- 测量工具条自身可用宽度并预留更多按钮、间距和内边距。拖动编辑区分栏、开关侧栏、字体加载、缩放和窗口变化都重新计算；不能只看浏览器窗口断点。
- 测量与布局分离，避免元素被隐藏后读到零宽而反复闪烁；聚焦项被收纳时保持可预测的焦点去向。极窄布局至少保留“更多”，所有功能仍能访问。
- 图标按钮有可访问名称和触屏点击空间；容器宽度够时不用大片留白换取全量菜单。

## 提示与菜单浮层

截图能确认提示文字被裁切，静态代码还显示 `.editor-pane` 等祖先设置了 `overflow: hidden`，提示为按钮伪元素。实施时用实际浏览器确认裁切祖先与层叠上下文；不能仅提高伪元素 `z-index` 就宣称解决。

建议使用共享浮层容器 / React Portal，把提示和溢出菜单放到编辑面板裁切边界外，以按钮视口坐标定位；已有适用能力应复用。层级应高于侧栏、编辑区和预览区，低于正在阻断页面的模态框。容器层叠上下文彼此隔离，依据见 [MDN 层叠上下文](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Positioned_layout/Stacking_context)。

浮层需做视口碰撞处理，首个按钮左侧空间不足时改为左对齐，接近顶部时向下显示；滚动、缩放、分栏调整时重新定位。Tooltip 不抢焦点或拦截点击，支持键盘聚焦提示；触屏不能依赖 Tooltip 才知道用途。菜单跟随焦点与 Esc 正常关闭，不把全局 `overflow` 全改为可见破坏编辑滚动。

## 验收

1. 三种顶栏状态（常规、自动隐藏、触屏）均找不到图床 / AI 入口；带旧启用配置启动后也没有上传、模型列表或生成请求，普通正文和外链图片不被改写。
2. 文件菜单导入、即时导出、取消、重复选择和存储失败均保留原有行为；侧栏释放空间，焦点与文件选择器不因菜单卸载失效。
3. 编辑区由宽到窄连续拖动，工具逐步进入菜单且不丢失、不重复；包含中文字体、页面缩放、侧栏展开 / 收起和无 `ResizeObserver` 时的降级验证。
4. 浅色 / 深色、左边界、靠顶部、窄屏下的 Tooltip 与菜单不被侧栏或面板裁切；按键与触屏操作独立检查。
5. 执行相关组件 / 布局行为测试、Lint 与 Web 构建；阶段 PR 跑完整 Web 基线。浏览器必须检查实际布局，jsdom 通过不等于浮层显示正确。
