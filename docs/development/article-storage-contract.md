# 文章存储契约与迁移恢复

状态：2026-10-14，P2a 已完成存储契约、迁移恢复原型及**浏览器备份升级入口和实际文章读写接入**，均为本地实现。目录包仍为合成原型，图片写入尚未开放。产品目标见 [文章目录与资源](../planning/article-assets.md)；原型证据见 [原型记录](../records/2026-10-14-article-storage-prototype.md)，产品入口证据见 [接入记录](../records/2026-10-14-browser-article-storage.md)。

## 现有数据来源与接入边界

- 浏览器文章仍来自 `historyStore` / `historyDb` 的 `wemd-history`，`HistorySnapshot.markdown` 包含完整源文。新库直接初始化 v3；已有 v2 经备份确认升级。没有另建一套无人读取的文章库，`wemd-files` 的 schema 与行为不变。
- `browserArticleDatabase` 负责正式浏览器文章存储；`browserArticlePrototype` 复用同一实现，但继续限制合成数据库前缀。原型恢复只写入新合成库，不能据此声称已有产品恢复入口。
- 目录模式的现有文本读写保持可用。`DirectoryArticlePrototype` 仍只接受 `radishink-p2a-prototype-` 合成根目录，捕获已授权句柄与文章目标；文章包、日志恢复和资源生命周期的产品入口待下一步。
- `StorageAdapter` 继续承担现有文本文件与目录操作。`ArticleStore` 表达文章和资源的一致性单元，不把 Blob 转成字符串塞进 `writeFile`。

## 文章与资源契约

`ArticleStore` 实例固定 `articleId` 和工作区；`read()` 返回完整 `ArticleSnapshot` 或不存在的 `null`，`commit(content, expectedRevision)` 保存同一快照，`recover()` 明确处理未完成操作。

| 字段 / 行为 | 存储约定                                                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `article`   | 复用 `HistorySnapshot`，保留 ID、完整 Markdown、时间、主题、自定义 CSS 和未知字段。旧记录缺失标题 / 创建时间时，只在读取结果补齐既有默认值，不重写迁移源  |
| `filePath`  | 保留为历史兼容信息，不能替代实例捕获的写入目标；不能将历史路径当作浏览器资源位置                                                                          |
| `revision`  | 新文章为 0，后续提交递增；创建时预期为 `null`，保存时必须提供已读版本。冲突明确失败，保留调用方当前编辑                                                   |
| `assets`    | 相对路径与原始 Blob；同一提交同时包含正文、全部保留资源与版本。存储层验证字节完整性，不承担图片解码 / 类型策略                                            |
| 资源可变性  | 已保存资源不可同名覆盖或隐式删除；移除正文引用仍保留字节，撤销和显式清理在后续阶段接入                                                                    |
| 错误        | 校验、冲突、容量、待恢复、能力不支持和升级占用有明确错误码；权限 / 配额 / 磁盘错误保留原始异常，不返回空文章或成功                                        |
| 异步归属    | 调用时复制文章与资源清单，Blob 本身不可变；实例固定目标。现有切换检查文章与正文是否仍一致；图片接入还须检查工作区与编辑锚点，不把后台完成自动插入当前选区 |

正文按原字符串保留 BOM、CRLF、未知 frontmatter 与已有外链。目录读取使用严格 UTF-8 解码并保留 BOM，不通过重新生成 frontmatter 完成迁移。资源校验使用 SHA-256 与字节数；摘要用于完整性检查，不代表身份认证。

目录名在创建时生成并持久保存，采用安全标题加文章 ID 摘要的 12 位后缀，内部为 `index.md` 与单数 `asset/`。标题更改不自动改目录。后缀仅用于消歧，实际目标已存在时仍拒绝覆盖；不以“碰撞概率低”代替检查。

路径段拒绝分隔符、控制字符、百分号编码、前导点、末尾点 / 空格、保留名和非 NFC 名称。资源只允许 `asset/` 下单个文件；大小写 / Unicode 冲突拒绝。原型不提供任意 URL 下载、路径清洗后静默接受或目录递归删除。

## 浏览器迁移与恢复

正式入口对现有 `wemd-history` 原位升级；本轮所有验证仅使用隔离浏览器中的合成数据，没有访问或迁移用户文章：

1. 启动先探测版本，v2 只显示备份升级提示，暂停编辑和写入。`readHistoryBackup` 在只读事务内导出原始键和值，核对记录结构及键 / ID 一致性。界面发起 JSON 下载后仍需用户确认文件保存成功，下载事件不等于磁盘备份已完成。备份只覆盖旧历史文章，不含站点设置、目录或外链图片。
2. `openBrowserArticleDatabase` 升级 v2 时要求该备份；升级事务内保留 `history`，新增 `articleRevisions`、`articleAssets`、`articleMigration`。资源按文章 ID 索引，备份和完成记录随升级事务提交。
3. 升级时再次读取源文，与备份逐项比较。备份过期、坏记录或事务中止均回滚 schema 与新增记录，不清库重建；重新备份后可重试。
4. 旧标签页占用时返回 `blocked`；即使稍后解除占用，被拒绝的请求也不能迟到升级。调用方关闭旧连接后重新发起。
5. 已打开实例收到 `versionchange` 后关闭连接并显示停止写入提示。不兼容版本（包括尚未支持的 v1 和未来版本）拒绝读取 / 写入，不降级或清库。历史 v2 客户端请求会得到 `VersionError`；无法替旧构建增加提示，其旧界面可能显示空列表，不能据此认为文章已丢失。
6. `restoreHistoryBackup` 已演练将升级前文章备份还原到**全新的合成 v2 数据库**，已有目标明确拒绝。用户可操作的 JSON 恢复 / 合并入口尚未提供，后续应采用新目标恢复，不覆盖或降级现库。备份不包含 v3 之后新增的正文更改或资源，也不是整站配置备份。

常规提交把 `history`、资源和版本放在同一读写事务；先在事务外计算摘要，避免等待非 IndexedDB 异步工作使事务失活。必须等待事务完成后才返回成功。两个连接的并发保存通过事务内版本比较裁决。

产品已采用“30 篇显式新建上限、已有文章不自动淘汰”的策略。迁移前超过 30 篇也完整保留并允许更新；UI 显示数量及处理说明，达到上限拒绝新建 / 导入，事务层同样检查数量。删除和清空须显式确认正文与资源范围；事务核对已读版本，清空还核对文章集合，冲突时整笔中止。

## 浏览器文章读写与失败行为

`historyDb` 持有已读取的文章版本和资源，`historyStore` 继续服务现有文章列表、Markdown 导入、改名与自动保存。更新提交完整文章及原有资源，不通过临时重读版本绕开冲突。同页写操作串行，保存捕获文章 ID；跨标签页依靠 IndexedDB 事务内的版本比较拒绝覆盖。

- 读取失败保留原状态并显示错误，不生成空列表或示例文章。初始化成功后重复挂载不重复读取并切走当前文章；返回浏览器模式后自动保存仍有效。
- 自动保存保留 10 秒间隔；`Ctrl/Meta+S` 也接入实际浏览器文章写入。只有事务完成才更新内存已存快照、提示成功，失败保留编辑并提供独立的“下载当前正文”入口。
- 选择当前文章不重新套用旧快照；切换 / 新建等待保存后复核文章与正文。写入期间继续输入时保留当前编辑，新建成功的文章可留在列表稍后打开。
- 不依赖页面关闭时的异步提交保证保存；有未保存正文时使用浏览器离开提示。仍应等待保存完成或主动下载，强制结束进程不能保证未提交输入落盘。
- 跨标签冲突不自动合并或覆盖：当前编辑可下载，随后刷新页面读取数据库中的版本。已加载列表不会由“重试读取”静默替换；初始化读取失败才提供重试入口。后续恢复界面再提供更完整的对比与合并。

当前二进制存储虽能保留、校验及随文章删除资源，产品尚未允许粘贴图片，也尚未提供含资源的备份 / ZIP 导出。不能把纯 Markdown 下载称作完整文章包备份。

## 目录迁移与恢复

旧散落 Markdown 只通过显式 `copyLegacy` 复制到一个新文章目录，原文件及同目录其他文章保留。复制前核对调用方捕获的源文，记录源文件摘要；恢复时来源变化则停止，不移动或删除原件。普通 `.md` 文件选择不授予相邻资源读取权，本原型不沿路径自动迁移旧图片。

工作区内部布局：

```text
合成工作区/
├── 旧文.md                            # 保留原件
├── 合成文章--身份后缀/
│   ├── index.md
│   ├── asset/
│   └── .radishink-owner.json           # 应用身份校验；标准编辑器无需它即可读文
└── .radishink-p2a/合成文章--身份后缀/
    ├── state.json                     # 已验证的提交状态
    ├── pending.json                   # 仅未完成操作存在
    └── 操作UUID/
        ├── journal.json               # 保留 before / after 与来源信息
        └── 资源文件                    # 校验过的暂存原字节
```

提交顺序为：读取并检查旧版本 → 暂存与校验资源 → 持久化日志 → 校验 / 认领空目标目录 → 写入资源 → 写入正文 → 重读校验 → 写完成状态 → 移除待恢复标记。资源先落盘，正文后引用。空文章仍保留 `asset/`。

日志落盘前失败不改目标文章，可重新提交；日志落盘后普通读取 / 保存报告“待恢复”，重建实例后由 `recover()` 继续完成。新文件 `createWritable` 失败可能留下空占位，已覆盖此边界；非空异值、原有资源缺失或变化、外部正文修改、日志损坏均停止恢复并保留证据。已提交状态但标记清理失败也可幂等恢复。

同源目录原型通过 Web Locks 串行处理；能力缺失时明确拒绝写入，无易失互斥降级。文件系统不提供跨文件原子事务或与外部编辑器共享的 CAS：本原型在关键步骤重读校验，但不能保证外部进程在最后校验与写入之间绝不改动文件。出现可检测冲突保留原件、目标与日志，后续需要可见的冲突处理入口。

暂存和操作日志保留，不自动递归清理；资源清理、配额治理、删除 / 移动 / 重命名整包和用户可操作的恢复界面仍属后续。此内部控制结构也需在正式接入前定义稳定版本与清理策略。

## 验证与后续接入条件

Vitest 使用合成 File System Access 替身验证各写入阶段失败、权限撤回、并发、资源保留和外部冲突。独立 Chromium 使用真实 IndexedDB、OPFS 与 Web Locks 验证事务、升级回滚、占用、重开和持久日志恢复。OPFS 是浏览器私有文件系统，不能代替系统目录选择器授权、真实磁盘满、断电或手机真机。

本轮不接入粘贴 / 选图、对象 URL 预览、ZIP、图片复制或服务器。下一步先完成目录文章包接入、用户可操作的恢复 / 冲突界面与生命周期，再启用图片写入。图片格式与尺寸限额仍待 P2a 后续测量；P2b 继续负责跨存储 ZIP 往返与公众号图片复制验证。
