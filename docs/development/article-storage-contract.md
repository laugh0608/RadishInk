# 文章存储契约与迁移恢复

状态：2026-10-19，P2a 已完成存储契约、迁移恢复原型、浏览器备份升级 / 实际文章读写，以及目录文章包、恢复 / 冲突入口、整包生命周期与旧 JSON 恢复入口，均为本地实现。本轮已接入图片粘贴 / 选图、资源预览与目录重新授权；证据见 [权限与图片记录](../records/2026-10-19-article-images.md)。产品目标见 [文章目录与资源](../planning/article-assets.md)；原型证据见 [原型记录](../records/2026-10-14-article-storage-prototype.md)，产品入口证据见 [浏览器接入记录](../records/2026-10-14-browser-article-storage.md) 与 [目录接入记录](../records/2026-10-14-directory-article-storage.md)。

## 现有数据来源与接入边界

- 浏览器文章仍来自 `historyStore` / `historyDb` 的 `wemd-history`，`HistorySnapshot.markdown` 包含完整源文。新库直接初始化 v3；已有 v2 经备份确认升级。没有另建一套无人读取的文章库，`wemd-files` 的 schema 与行为不变。
- `browserArticleDatabase` 负责正式浏览器文章存储；`browserArticlePrototype` 复用同一实现，但继续限制合成数据库前缀。原型恢复只写入新合成库；产品另提供经预览确认的缺失 ID 合并恢复。
- 目录模式由 `FileSystemAdapter` 接入 `DirectoryArticleWorkspace` / `DirectoryArticleStore`。新建 / Markdown 导入形成真实文章包，旧文本保留原位；列表将包折叠成一篇文章。`DirectoryArticlePrototype` 仍限制合成前缀并保留旧原型布局，复用正式写入算法。
- `StorageAdapter` 继续承担现有文本文件与目录操作。`ArticleStore` 表达文章和资源的一致性单元，不把 Blob 转成字符串塞进 `writeFile`。

## 文章与资源契约

`ArticleStore` 实例固定 `articleId` 和工作区；`read()` 返回完整 `ArticleSnapshot` 或不存在的 `null`，`commit(content, expectedRevision)` 保存同一快照，`recover()` 明确处理未完成操作。

| 字段 / 行为 | 存储约定                                                                                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `article`   | 复用 `HistorySnapshot`，保留 ID、完整 Markdown、时间、主题、自定义 CSS 和未知字段。旧记录缺失标题 / 创建时间时，只在读取结果补齐既有默认值，不重写迁移源 |
| `filePath`  | 保留为历史兼容信息，不能替代实例捕获的写入目标；不能将历史路径当作浏览器资源位置                                                                         |
| `revision`  | 新文章为 0，后续提交递增；创建时预期为 `null`，保存时必须提供已读版本。冲突明确失败，保留调用方当前编辑                                                  |
| `assets`    | 相对路径与原始 Blob；同一提交同时包含正文、全部保留资源与版本。存储层验证字节完整性，不承担图片解码 / 类型策略                                           |
| 资源可变性  | 已保存资源不可同名覆盖或隐式删除；移除正文引用仍保留字节，撤销和显式清理在后续阶段接入                                                                   |
| 错误        | 校验、冲突、容量、待恢复、能力不支持和升级占用有明确错误码；权限 / 配额 / 磁盘错误保留原始异常，不返回空文章或成功                                       |
| 异步归属    | 调用时复制文章与资源清单，Blob 本身不可变；实例固定目标。现有切换检查文章与正文是否仍一致；图片接入检查工作区与编辑锚点，不把后台完成自动插入当前选区    |

正文按原字符串保留 BOM、CRLF、未知 frontmatter 与已有外链。目录读取使用严格 UTF-8 解码并保留 BOM，不通过重新生成 frontmatter 完成迁移。资源校验使用 SHA-256 与字节数；摘要用于完整性检查，不代表身份认证。

目录名在创建时生成并持久保存，采用安全标题加文章 ID 摘要的 12 位后缀，内部为 `index.md` 与单数 `asset/`。标题更改不自动改目录。后缀仅用于消歧，实际目标已存在时仍拒绝覆盖；不以“碰撞概率低”代替检查。

路径段拒绝分隔符、控制字符、百分号编码、前导点、末尾点 / 空格、保留名和非 NFC 名称。资源只允许 `asset/` 下单个文件；大小写 / Unicode 冲突拒绝。存储层不下载任意 URL，也不通过清洗路径静默接受非法输入。目录产品的整包移动 / 删除仅经下述归属校验与恢复副本流程执行；原型不开放任意目录递归删除。

## 浏览器迁移与恢复

正式入口对现有 `wemd-history` 原位升级；本轮所有验证仅使用隔离浏览器中的合成数据，没有访问或迁移用户文章：

1. 启动先探测版本，v2 只显示备份升级提示，暂停编辑和写入。`readHistoryBackup` 在只读事务内导出原始键和值，核对记录结构及键 / ID 一致性。界面发起 JSON 下载后仍需用户确认文件保存成功，下载事件不等于磁盘备份已完成。备份只覆盖旧历史文章，不含站点设置、目录或外链图片。
2. `openBrowserArticleDatabase` 升级 v2 时要求该备份；升级事务内保留 `history`，新增 `articleRevisions`、`articleAssets`、`articleMigration`。资源按文章 ID 索引，备份和完成记录随升级事务提交。
3. 升级时再次读取源文，与备份逐项比较。备份过期、坏记录或事务中止均回滚 schema 与新增记录，不清库重建；重新备份后可重试。
4. 旧标签页占用时返回 `blocked`；即使稍后解除占用，被拒绝的请求也不能迟到升级。调用方关闭旧连接后重新发起。
5. 已打开实例收到 `versionchange` 后关闭连接并显示停止写入提示。不兼容版本（包括尚未支持的 v1 和未来版本）拒绝读取 / 写入，不降级或清库。历史 v2 客户端请求会得到 `VersionError`；无法替旧构建增加提示，其旧界面可能显示空列表，不能据此认为文章已丢失。
6. `restoreHistoryBackup` 保留新合成 v2 库的原型演练。正式产品提供“恢复旧 JSON 备份”：校验格式 / 数据库归属 / 重复 ID，预览新增与跳过的文章，确认后只添加现库缺失的 ID，同 ID 现文始终保留。事务再次检查预览时的 ID 集合和版本；变化或写入失败整批回滚，不降级、覆盖或清库。恢复保留全部旧文，可超过 30 篇，之后仅拒绝新建；单次文件上限 20 MiB、1000 篇。备份不含 v3 后续更改、资源或站点配置。

常规提交把 `history`、资源和版本放在同一读写事务；先在事务外计算摘要，避免等待非 IndexedDB 异步工作使事务失活。必须等待事务完成后才返回成功。两个连接的并发保存通过事务内版本比较裁决。

产品已采用“30 篇显式新建上限、已有文章不自动淘汰”的策略。迁移前超过 30 篇也完整保留并允许更新；UI 显示数量及处理说明，达到上限拒绝新建 / 导入，事务层同样检查数量。删除和清空须显式确认正文与资源范围；事务核对已读版本，清空还核对文章集合，冲突时整笔中止。

## 浏览器文章读写与失败行为

`historyDb` 持有已读取的文章版本和资源，`historyStore` 继续服务现有文章列表、Markdown 导入、改名与自动保存。更新提交完整文章及原有资源，不通过临时重读版本绕开冲突。同页写操作串行，保存捕获文章 ID；跨标签页依靠 IndexedDB 事务内的版本比较拒绝覆盖。

- 读取失败保留原状态并显示错误，不生成空列表或示例文章。初始化成功后重复挂载不重复读取并切走当前文章；返回浏览器模式后自动保存仍有效。
- 自动保存保留 10 秒间隔；`Ctrl/Meta+S` 也接入实际浏览器文章写入。只有事务完成才更新内存已存快照、提示成功，失败保留编辑并提供独立的“下载当前正文”入口。
- 选择当前文章不重新套用旧快照；切换 / 新建等待保存后复核文章与正文。写入期间继续输入时保留当前编辑，新建成功的文章可留在列表稍后打开。
- 不依赖页面关闭时的异步提交保证保存；有未保存正文时使用浏览器离开提示。仍应等待保存完成或主动下载，强制结束进程不能保证未提交输入落盘。
- 跨标签冲突不自动合并或覆盖：当前编辑可下载，随后刷新页面读取数据库中的版本。已加载列表不会由“重试读取”静默替换；初始化读取失败才提供重试入口。后续恢复界面再提供更完整的对比与合并。

当前产品已允许粘贴 / 选择图片，尚未提供含资源的备份 / ZIP 导出。不能把纯 Markdown 下载称作完整文章包备份。

## 目录迁移与恢复

旧散落 Markdown 只通过显式 `copyLegacy` 复制到一个新文章目录，原文件及同目录其他文章保留。复制前核对调用方捕获的源文，记录源文件摘要；恢复时来源变化则停止，不移动或删除原件。普通 `.md` 文件选择不授予相邻资源读取权，当前产品不沿路径自动迁移旧图片。

正式目录包使用版本 1 控制结构；旧原型 `.radishink-p2a/` 不自动迁移成产品数据。标准编辑器仍可直接打开 `index.md`，不依赖控制记录阅读正文。

```text
工作区/
├── 旧文.md                              # 保留原件
├── 文章--身份后缀/
│   ├── index.md
│   ├── asset/
│   ├── .radishink-owner.json             # 文章 ID / format: 1
│   └── .radishink/
│       ├── state.json                   # 已验证的提交状态
│       ├── pending.json                 # 仅未完成写入存在
│       ├── lifecycle.json               # 仅原包的未完成移动 / 删除存在
│       └── 操作UUID/
│           ├── journal.json             # before / after 与来源摘要
│           └── 资源文件                  # 校验过的暂存字节
└── .radishink-operations/操作UUID/
    ├── operation.json                   # 整包源 / 目标与完整字节清单
    ├── package/                         # 移动 / 删除前的整包恢复副本
    ├── target-claimed.json               # 移动目标占用步骤
    └── complete.json                    # 操作完成后写入
```

写入先校验旧版本，暂存资源并写持久日志，再写资源、正文、重读校验及完成状态，最后移除 pending。原型与产品均保留空 `asset/`；新创建目录先校验所有权，不能认领已有陌生目录。pending 发布前失败的暂存不会被当作成功文章，列表可以显示未完成包；尚未形成有效日志的占位保留供磁盘检查。pending 发布后，普通读取 / 保存暂停，由“目录维护与恢复”显式推进。

恢复验证来源摘要、文章 ID、before / after、暂存字节及目标原内容。自己失败创建的零字节占位可以补写；非空异值、原有资源缺失 / 变化、外部正文修改或坏日志均停止并保留证据。已写状态但 pending 清理失败可幂等恢复。当前编辑不会随恢复结果自动覆盖；用户可下载正文并确认重新读取，或将当前编辑及已读资源快照另存成新 ID 副本继续写作。旧单文件的副本只含正文，不自行读取相邻图片。

标题更新只改元数据，目录和文章 ID 不变。移动按目录整体执行，包含资源和隐藏控制记录；删除前说明整包范围。生命周期操作先创建并校验完整恢复副本、发布日志及原包操作标记，再写移动目标、验证目标与原包、删除原包、写完成标记。未完成生命周期标记禁止继续写原包；重开后可从维护入口继续。目标非空异值或源包变化时停止；系统递归删除若部分失败，保留副本并要求人工检查，不在无法确认来源时继续清空。

文章包出现陌生顶层文件或未登记资源时拒绝移动 / 删除；通用文件夹操作不能绕过文章保护，包含文章包的文件夹需逐篇处理。整包操作完成后恢复副本仍保留在磁盘，维护入口可显式永久清理。文章旧提交日志也只能显式清理：先校验当前包，拒绝 pending，再识别本文章的已提交日志及资源摘要；未知或未发布暂存保留。移除图片引用仍不删除当前 `asset/` 字节，孤立资源清理不在本轮范围。

同源目录读写与生命周期共用 Web Locks；能力缺失明确拒绝文章写入。文件系统不提供跨文件事务或与外部编辑器共享的 CAS，最后校验到写入 / 删除之间仍存在外部进程竞争窗口。可检测冲突保留原件、目标与日志；不能把此实现称作跨文件原子提交。

旧文本保存、删除、改名检查已读原文，外部修改不静默覆盖。`.wemd/themes.json` 沿用原有主题后端，不混入文章包。并发启动恢复复用同一适配器初始化，避免 StrictMode 重入关闭正在使用的目录句柄。

## 验证与后续接入条件

Vitest 使用合成 File System Access 替身验证各写入阶段失败、权限撤回、并发、资源保留和外部冲突。独立 Chromium 使用真实 IndexedDB、OPFS 与 Web Locks 验证事务、升级回滚、占用、重开和持久日志恢复。OPFS 是浏览器私有文件系统，不能代替系统目录选择器授权、真实磁盘满、断电或手机真机。

本轮已接入粘贴 / 选图、对象 URL 预览与系统目录重新授权；ZIP、可用的本地图片复制与服务器仍未开放。真实系统目录授权 / 撤权 / 标签重开与 OPFS 替身分别记录在 [权限与图片记录](../records/2026-10-19-article-images.md)。P2b 继续负责跨存储 ZIP 往返与公众号图片复制验证。

## 图片写入与预览

- 接受 PNG、JPEG、WebP、GIF；单图 10 MiB、1600 万像素，每次 10 张、总计 32 MiB。先校验文件头与尺寸，再实际解码；默认保存原字节，不压缩、不去重、不下载外链。限额实测与适用范围见本轮记录。
- 图片必须属于已打开的浏览器文章或目录文章包。旧单文件提示用户在目录维护中显式复制，原件保留，不自动读取相邻图片。
- 浏览器图片写入与正文保存共用现有写队列；目录工作区同样串行两类提交。先用最近已提交的正文和全部资源提交新字节，成功后才向编辑器插入 `asset/image-<UUID>.<扩展名>`；新的正文引用随后按普通自动 / 手动保存提交。不是跨存储与编辑器的原子事务：中途取消或关闭可能留下未引用资源，但不会产生引用已提交而资源未提交的成功状态。
- 插入锚点随正文编辑移动，重新移动光标不会改变原目标。覆盖原选区、撤销 / 重做、文章 / 工作区切换、显式取消阻止迟到插入；已开始的存储提交可以完成并保留资源，不立即删除。逐图格式失败单独提示，成功项保持原顺序；同次粘贴的纯文本保留。
- 预览从当前文章资源派生 Blob URL；在惰性模板中解析路径后才挂载 DOM，缺失 / 越界资源列出提示并移除请求源，不发往站点根路径。切换、资源更新、卸载释放 URL；异步读取取消后不再创建 URL。正文不写入临时 URL。
- 含本地 / Blob 图片时，两种复制在写剪贴板前明确失败，不显示完整复制成功，也不隐式上传。已有外链、内联 data 图片与应用装饰图沿用原流程。纯 Markdown 下载仍不携带图片。

## 系统目录权限恢复

启动只查询保存的目录句柄权限，不在无用户手势时弹选择器或请求授权。缺少句柄 / 权限时保留文件夹模式并显示重新授权 / 重选入口；不伪装已就绪或静默换成浏览器模式。已打开文章撤权后，失败提示保留编辑；目录维护内可重新授权原句柄，成功后重试保存。若网站设置已禁用文件修改，需要先恢复该设置。句柄数据库读取失败仍显式报错。
