# P3-2 本地账号与文章 API

日期：2026-10-25。基线为 `dev` 的 `4a354e9`，起始工作区 / 暂存区干净，领先 `origin/dev` 2 个提交。本轮按用户要求直接实施和本地验证；后续按用户明确要求复查并纳入 `dev` 本地提交，没有推送、部署、外部账号变更或真实数据迁移。操作说明集中在 [本地账号与 HTTP](../development/server-http.md)。

## 结果

- Nest 入口撤下旧上传模块、公开 uploads 静态路由和宽泛 CORS，按显式配置只监听 loopback。无管理员不 ready；不支持的共享 HTTP 模式拒绝启动。
- schema 2 增加本地账号、会话摘要和持久限速；保留 schema 1 原 SQL / 摘要，升级需显式离线完整文件备份与摘要校验。管理员初始化、普通账号创建、密码恢复、禁用 / 启用经本机 TTY 命令执行。
- Argon2id、随机会话、Cookie、登录前浏览器绑定、CSRF、精确 Origin / Host、失败限速、会话轮换 / 撤销均接入。管理员没有文章越权例外。
- 文章列表 / 完整快照 / multipart 保存 / 删除墓碑 / revision 资源读取接入正式仓储。客户端身份不进入授权；未知正文与元数据保留。API 错误统一分类并携带 requestId，不输出 SQL、磁盘路径或正文。
- 文件仓储迁入有界 worker，上传开始即占提交槽；主线程只保留协议处理与短身份 SQL。提交与删除在事务内复核会话；文件校验在事务外，启动维护逐篇释放正文。
- 图片完成真实完整解码，含动画累计像素、截断 / 压缩损坏与格式伪装负向测试。旧资源复用、操作回执、版本冲突与越权由真实 HTTP 测试覆盖。

## 依赖

新增固定 `argon2@0.45.1`、`sharp@0.35.5`、`busboy@1.6.0`、`@types/busboy@1.5.5`，由 pnpm 9.0.2 更新锁文件；现有直接依赖未升级，锁文件仅增加依赖条目。Argon2 安装脚本与实际加载均成功。`better-sqlite3` 的既有安装例外保持，未扩大忽略脚本范围。

最后执行离线冻结锁文件复装时，本机缓存缺少既有 ESLint tarball，pnpm 已开始重建 `node_modules` 后退出；随后使用 `ELECTRON_SKIP_BINARY_DOWNLOAD=1 CI=true mise exec -- pnpm install --frozen-lockfile` 联网恢复成功，锁文件与依赖版本未变化，并重跑服务端基线和 Web 构建。离线失败是安装环境证据，不能标为离线安装通过。

已核对安装包许可：argon2 / busboy / 类型包为 MIT，Sharp 为 Apache-2.0；`@img/sharp-libvips-*@1.3.4` 的 README 列出 libvips 及其 LGPLv3、MIT、BSD、MPL 等传递组件与来源。图片库原生二进制保留在依赖与临时下载缓存，不进入 Git，也未进入 Web bundle。P4 分发镜像时仍需携带完整第三方许可与对应源码 / 构建来源，不能只附 Sharp 的 Apache 文本。库使用依据见 [Argon2](https://github.com/ranisalt/node-argon2)、[Sharp constructor](https://sharp.pixelplumbing.com/api-constructor/)、[Busboy](https://github.com/mscdex/busboy)。

## 容量实测

[独立进程探针](../../apps/server/test/http-runtime.cjs) 先为 Alice 写入 999 篇合成小文章，再由四个账号同时提交：每篇含 5 MiB 正文、9 张独立随机 PNG，正文与资源合计 **63.05 MiB**。Alice 达到 1000 篇后再创建明确 507；最终 1003 篇，保留文件约 **252.67 MiB**，重开维护检查通过。RSS / 事件循环数据来自独立服务进程，排除客户端 FormData 缓冲；CPU 统计包含服务线程。

| 环境                                    | 两次并行 Argon2 hash | 999 篇预置 | 四篇完整提交 | 同时健康请求 | 服务峰值 RSS | 主线程最大 / P99 事件循环延迟 |
| --------------------------------------- | -------------------- | ---------- | ------------ | ------------ | ------------ | ----------------------------- |
| macOS arm64 / APFS                      | 17.0 ms              | 178.1 s    | 1694.7 ms    | 10.4 ms      | 1154.3 MiB   | 23.5 / 13.9 ms                |
| Linux arm64 / tmpfs，2 CPU / 4 GiB 容器 | 18.4 ms              | 60.4 s     | 974.8 ms     | 18.8 ms      | 894.4 MiB    | 70.1 / 48.6 ms                |

macOS / Linux 服务 CPU 分别约 1371 / 1173 ms。初次文件总量与四篇逻辑数据接近，额外为合成小文和快照清单；后续修改仍产生历史快照，保留空间受配额限制，不据此承诺固定放大率。预置过程包含逐次文件扫描 / fsync，耗时随工作区增长；本次证明主线程不做同步文件扫描及四槽限额可执行，不代表任意历史规模的吞吐保证。

Linux x64 最终小型原生 smoke（本机兼容层）两次 hash 26.4 ms、四篇提交 99.7 ms、峰值 RSS 228.1 MiB；arm64 为 16.5 ms、28.6 ms、194.5 MiB。x64 没有执行近满额容量探针，不能套用 arm64 数字。

Linux 复用 `node:22.23.3-bookworm-slim`，digest 为 `sha256:3ed98443660ff48413b5af19ecefce3b9d50845a901a43420d47cc63a9fddbe9`；只读挂载仓库与 Linux Sharp 原生包、非 root、禁网、无发布端口，合成数据在 tmpfs，容器 `--rm`。仅额外下载锁定的 Linux arm64 / x64 Sharp 原生包至 `/private/tmp/radishink-p3-2-linux-native`，不修改系统工具链。峰值包含特定平台分配器 / GC 行为，不能作为部署内存硬上限；P4 仍需真实持久卷和部署资源预算。

## 提交前复查

2026-10-25 按用户要求复查授权、提交事务、请求限额与全部修改范围。发现 Busboy 在达到配置限额时即发出事件，原处理会误拒绝恰好 125 张资源或恰好 10 MiB 的合法图片；改为保留一个拒绝哨兵，业务上限保持原值。越界测试还暴露限额回调中同步销毁 parser 会触发 Busboy 内部空引用，已改为暂停输入后延迟销毁，避免异常逃逸。新增真实 HTTP 边界测试，确认恰好上限成功、126 张与多 1 字节仍明确 413。服务端 Lint / build 与 78 项测试通过；此前完整 Web、双架构故障与容量证据继续保留，未推送或部署。

## 剩余边界

本轮 HTTP 验证均为 loopback 自动化；真实浏览器 Cookie / CSRF 与 P3-3 Web 私有缓存、退出多标签、离线 / ZIP / 冲突交互尚未验收。P3-4 OIDC、共享 HTTP 模式、P4 Compose / 备份恢复 / epoch 轮换仍待实施；没有对外开放或真实数据迁移。P1 / P2 手机真机与真实公众号验收继续延后。

P3-1 的两个本地提交仍未推送；新增服务端 CI 矩阵没有远程运行结果，Ruleset 未变。P3-2 已按后续授权复查并纳入本地提交；未创建 PR、tag、Release 或部署。测试服务与容器结束后关闭，未保留监听服务。
