## 授权与起点

用户要求先提交工作区更改，再继续下一步开发。先复查并提交分发材料为 `4d04bdb`（`build(distribution): 补齐 P4 镜像材料与校验门禁`），提交后工作区干净，`dev` 本地领先远程跟踪引用一个提交；未 fetch 或推送。本批从该提交串行继续，不创建分支 / worktree，不使用子代理。

首次暂存区检查发现两份原始通知展示副本的混合空格 / Tab，按生成规则统一展示缩进，并重新核验 760 处来源与 85 项治理用例。原始源码和成员摘要不变，没有放宽 Git 门禁；这些修正已纳入上面的提交。

## 实现范围

- 提供独立的拉取式 Compose、公开配置与 release lock 示例。沿用双服务、SQLite / 文件卷、非 root 和已有 CLI；不引用浮动别名、不自动创建空工作区。两份固定镜像同时绑定完整 tag、源 revision、平台、实际单平台 manifest digest 和 OCI 来源。
- 增加无网络、源卷只读的配置 / 身份 / schema 预检，以及拉取镜像、停入口 / 后端、备份、独立恢复验证、显式升级、存储检查、ready 与同源能力核验的编排。备份使用独立 local 卷；部署 JSON 仅写入操作员私有状态目录，不保存配置全文或秘密。
- 使用私有文件锁与 daemon 级唯一维护锁容器，记录阶段与失败依据。可能变更数据后失败拒绝直接重试且不覆盖原失败记录；通过新目标恢复、epoch 轮换和显式配置变更继续。失败的独立恢复目标保留为证据，不被应用挂载。
- 发布元数据支持 Web / server；停用模板准备双组件 / 双架构与相同源版本，发布前校验 `version.json`。模板继续停用，没有创建 tag、上传镜像、启用 Ruleset 或执行远程部署。
- CI 配置增加双架构最终镜像上的编排 smoke，仓库门禁和负向用例同步。正式发布的不可覆盖 / 成对记录、基础系统完整源码提供方式及真实 OIDC / 手机 / 公众号条件继续保留。

详细契约、命令、取消 / 恢复方式与局限见 [操作说明](../deployment/release-compose.md)。没有更改产品版本、存储 schema / 键、文章模型、迁移 SQL 或用户归属规则。

## 实际发现与验证

真实只读预检最初遇到 `SQLITE_CANTOPEN`：已关闭的 WAL 数据库会尝试创建 SHM。改为在无 WAL 时复制已检查点主库到探针 tmpfs 查询，同时检测复制期间变化；有 WAL 时读取现有只读视图，禁止 immutable 忽略 WAL。源卷始终只读，普通完整检查仍在停机后由原 CLI 执行。

实际环境为 Node `22.23.3` / pnpm `9.0.2`、Docker `29.8.2`、Compose `5.5.0`，镜像 Node `22.23.4`，均沿用现有工具与固定基础镜像，没有升级依赖或全局设置。

- `mise exec -- pnpm validate:web`：退出 0，治理 107 项、core 64 项、Web 802 项及 Lint / TypeScript / Vite / PWA 构建通过。保留 12 条既有 ESLint warning、Baseline 数据过期、混合静态 / 动态导入与大 chunk 提示，未放宽门禁。
- `mise exec -- pnpm validate:server`：退出 0，服务端 Lint、构建和 116 项测试通过。
- 分别构建 `linux/arm64` / `linux/amd64` 的最终 Web / server 镜像，四次构建均退出 0。对每个架构运行 `check:image-distribution --server <镜像> --web <镜像>`，207 个物理包、391 份源码、原始基础通知、Sharp / SQLite / Argon2 实测全部通过；覆盖提交前通知展示缩进修正后的材料。
- 对两架构串行运行 `test:deployment --server <镜像> --web <镜像>`，均退出 0。真实 CLI 的 preflight / apply、schema 3 账号管理员预检、共享安装、固定镜像再次部署、正文 / 原始 PNG 和 HTTP 保存均通过。
- 错误 OCI revision、缺失本地镜像在停机前拒绝且原入口仍可用；备份目录实际权限拒写、备份清单损坏、存储未知路径与真实健康检查失败分别在目标阶段停止，记录与入口状态按预期保留。
- 损坏备份留下独立验证卷名称；可能变更数据后的失败阻断同卷重试且不覆盖前次记录。通过备份恢复到新卷，显式更换目标并再次部署通过，旧 epoch 读取返回 409，正文 / 原图仍一致。
- 独立合成 schema 2 卷经显式 `--upgrade` 升至 3；另一次在迁移 CLI 启动边界触发 AbortController 取消，入口保持停止、拒绝直接重试，恢复到另一新卷后升级 / 启动 / 文章验证通过。这不是迁移事务中途 SIGKILL 或物理断电证据。
- 单元负向用例还覆盖不完整旧记录、别人的文件锁、停止失败不能伪称入口关闭、平台 digest / descriptor / 非 root 用户、tag 与源版本 / 轨道不符时不能输出发布元数据。`check:repo` 与 `git diff --check` 通过。
