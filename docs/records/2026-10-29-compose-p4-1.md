### 检查中修正的问题

- 原前端镜像缺少声明生成脚本、许可和 `version.json` 构建输入；补齐真实输入，未绕过声明生成或类型检查。Docker 安装层与源代码层分开并使用 BuildKit 缓存，修改源码不再重装全部依赖。
- 一次 Corepack 下载出现 `UND_ERR_SOCKET`，重试恢复；属于环境传输失败，未换源、改锁或忽略退出码。首次本地 Lint / 类型失败修正后重跑通过。
- Shell 的逐行正则不足以拒绝多行路径配置，增加完整字符白名单并用真实容器负向检查；显式空值也拒绝。独立静态镜像重启可能保留 `/tmp`，启动入口仅重新生成自己的产物目录，并实测不使用 tmpfs 的重启。
- Node `fetch` 会覆盖自定义 `Host`；协议夹具改用标准 `http.request` 保留受测 Host。重建检查关闭客户端连接复用，避免同步 Docker 操作阻塞事件循环后复用旧连接。服务端来源策略未放宽。
- 浏览器通过 SW 后部分响应体无法再被 CDP 读取；新身份检查使用实际 201 请求 URL，并等待产品导入完成提示。刷新验收明确从列表重新打开已唯一命名的回导文章，不假定产品会恢复上次选中项。

PWA 夹具最初轮询 registration 的 active 状态后刷新，测试页仍未受控；使用 `navigator.serviceWorker.ready` 明确等待就绪后再导航，随后完整配置更新流程通过。未强制 `clients.claim` / `skipWaiting`，未注销 Worker 或清库，也未修改产品更新门禁。

另实际停止本轮后端容器后，请求带合成查询串的 API：前端返回 `503` JSON / `no-store`，Nginx 日志不包含该查询串；恢复后 readiness 通过。这验证上游不可用时不会把 API 回退为静态 HTML 或把请求 URL 写入错误日志。
