## 实现

- 增加实际物理包目录的声明生成器、离线核验、固定源码下载和原始通知成员校验；失败不覆盖此前生成结果，源码下载没有静默替换来源。
- 保留三项 npm 补充证据；`invariant` 明确为保留发布署名的 MIT 组合声明，不把标准条款误作上游缺失文件或新授权。
- 保留 libvips 28 项组件版本、构建配方和 5 份补丁，加上 librsvg 锁定的 357 个 Rust 包，共 391 份归档 / 补丁，原始合计 216,872,843 字节。原始源码留在 Git 忽略目录并随服务端镜像交付；仓库记录来源、摘要和 386 份派生通知，追溯 760 个原始成员。
- 服务端元数据由历史 `UNLICENSED` 改为指向根许可，另附 Git 基线与新旧实现范围说明；旧上传 / COS 源码仍编译和分发，依赖仍纳入清单。未改变根许可、上游许可或依赖版本。
- 两份镜像保留基础层的版权和来源身份。服务端复制 Node / Debian 原文与公共许可，Web 保留 Nginx / 模块原文及 APK 原始数据库。基础系统的完整源码提供方式仍须在正式分发前复核，不把这些来源记录写作整镜像法律放行。
- CI 原生双架构任务增加最终双镜像构建与核验，聚合 context / Ruleset 名称保持不变；工作流与仓库门禁、负向测试同步。发布工作流继续停用，远程尚未运行本轮修改。

使用的上游依据与固定摘要保存在 [源码目录](../../LICENSES/distribution/native-sources.json) 和 [npm 来源](../../LICENSES/distribution/npm-sources.json)，完整操作及限制见 [分发说明](../deployment/image-distribution.md)。Pixman / Cairo 原发布站 TLS 握手失败，固定改用各项目官方 GitLab 的同版本 tag 归档；libtiff 固定使用官方 OSGeo 的同版本 release 归档。分别记录独立 SHA-256，非下载器自动 fallback。Cairo 两份归档共有的 895 个 C / C++ 源文件，以及 libtiff 的 137 个共有源文件逐字节一致。上游完整源码与派生文本分别留摘要，原始文件不改写。
