# P3 技术收敛与提交顺序实验

日期：2026-10-25。范围：服务器工作区技术设计与本地合成原型，不是后端产品交付。起点为 `dev` 的 `853d767`，工作区及暂存区干净；本轮没有新建分支、安装依赖、启动服务、接触真实文章、修改兄弟项目或进行远程发布。

## 现状核对与结果

核对 `apps/server/src/main.ts`、上传模块、包清单与 TypeScript 配置，以及现有 `StorageManager`、`StorageAdapter`、`ArticleStore` 和 P2 ZIP 限制。上游服务当前开启宽泛 CORS、匿名上传与公开静态资源，上传 service 含占位方法，尚无账号 / 文章一致性；根 Docker / Nginx 也仍是静态前端。因此不能直接把它标为 P3 服务器存储。

形成 [ADR 0002](../adr/0002-server-workspace-and-identity.md) 和 [P3 实施契约](../planning/server-workspace-contract.md)：沿用 NestJS / TypeScript，单实例 SQLite + 文件卷；不可变资源对象与正文快照，数据库事务发布当前版本；本地账号与 OIDC 共用内部所有者；同源 API、完整快照提交、幂等重试、可撤销 Cookie 会话、明确备份与模式迁移。原型也促使方案明确：文件是内容字节来源，但当前提交状态、身份与删除状态不能从孤儿文件重建。

## 可复现实验

实验源码为 [server-commit-probe.mjs](../../scripts/prototypes/server-commit-probe.mjs)。仅使用项目已有 Node 22.23.3 标准库与实验性 `node:sqlite`，不被应用导入，不是正式驱动接入或安全组件。每项测试创建系统临时目录下的 `radishink-p3-probe-*` 合成库 / 文件，结束时关闭连接并删除自己创建的目录。

```bash
mise exec -- node --test scripts/prototypes/server-commit-probe.mjs
```

结果：13 项通过，0 失败 / 跳过。Node 输出预期的 SQLite ExperimentalWarning，未压制。正式方案选择 `better-sqlite3`，其安装、精确版本、容器兼容性尚未验证。

| 实验                                                                   | 观察                                                                                      |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| BOM / CRLF / 未知 frontmatter 与合成资源字节                           | 原样往返，未重新序列化 Markdown                                                           |
| 子进程 SIGKILL：正文写一半、暂存完成、文件发布、事务内更新、事务提交后 | 前四处重开读原版本，最后一处读新版本；所有读取资源完整，随后同操作重试都收敛到 revision 1 |
| 两数据库连接先读同一版本再保存                                         | 后写者冲突，第一份内容保持                                                                |
| 文件已发布、数据库事务开始前插入竞争提交                               | 事务内再次核对版本，迟到提交不覆盖获胜者                                                  |
| 响应丢失后的同操作重试 / 后续已有新版本 / 异值复用操作 ID              | 原操作返回原 revision，不回退最新正文；异值明确拒绝，未变资源对象只存一份                 |
| 另一个所有者猜到文章 ID                                                | 仓储查询与写入拒绝；此项不是 HTTP 鉴权验证                                                |
| 注入 ENOSPC / 实际 SQLite 写锁占用                                     | 原始错误或 busy 传播，可见版本不推进                                                      |
| 完整孤儿快照 / 当前资源被篡改                                          | 孤儿不自动提升为已保存版本，当前资源摘要错误明确失败                                      |

实验以单篇文章和单个二进制资源缩小模型，使用平铺 generations / objects 目录；正式数据布局按所有者 / 文章隔离，实验不验证 HTTP 路径解析、图片真实性、配额、会话、幂等请求规范化、删除墓碑或清理。SIGKILL 是真实进程中止；ENOSPC 是注入错误，资源是合成字节，不是实际图片解码；均不能替代断电、磁盘满、容器卷或真实 Radish 验收。
