## ZIP 实现

唯一详细契约见 [文件进出](../planning/markdown-file-import-export.md#下一阶段文章包与文件菜单)，存储职责见 [文章存储契约](../development/article-storage-contract.md)。文件菜单默认提供 ZIP，保留纯 Markdown；全菜单共享忙碌状态。导出捕获最新编辑与固定资源，导入验证后才保存旧稿、用新身份提交整篇文章。没有账号、自动上传、外链下载或额外资源库。

- 浏览器正文 / 资源一起交给既有 IndexedDB 事务；目录使用同一 `DirectoryArticleStore` 日志与 pending 恢复。目标资源 close 失败时不发布成功快照，旧稿不变，待恢复包可明确重试。
- Worker 负责 ZIP 编解码、结构 / 大小 / CRC 检查；每次任务独立创建，完成、取消、错误或 30 秒超时后终止。主线程按图片策略验证解码，临时资源不写入旧文章。
- 单篇格式、64 MiB 包体 / 展开总量、128 条目、5 MiB 正文及既有图片限额；不支持 ZIP64、数据描述符、分卷、加密、符号链接、任意附件、批量文章或完整站点备份。
- 未引用但受支持的图片仍随包保存。缺图或读取失败停止默认 ZIP，外链保留并提示仍需网络；`srcset` / CSS 资源引用有明确不支持提示。纯文本导出继续用于故障抢救。
- 公众号 / HTML 复制遇到本地图片仍停止；帮助和错误提示改为可先导出 ZIP、解压后手工插图。这是可用的原图交付方式，不代表真实公众号自动转存已通过。

依赖选择为固定 `fflate 0.8.3`，MIT；来源为 [官方仓库](https://github.com/101arrowz/fflate) 与 [官方变更记录](https://github.com/101arrowz/fflate/blob/master/CHANGELOG.md)。该版本补充 ZIP64 相关修复；本应用首轮仍主动拒绝 ZIP64。使用标准 Worker 与流式 Inflate；图片导出用 STORE，避免无收益的重复压缩。只修改 Web 依赖与锁文件中的必要条目，撤去 pnpm 自动调整的无关间接解析，并以 offline / frozen-lockfile 重新链接验证。依赖声明由项目生成器输出，不手写生成产物。
