# PWA 安全更新与升级验证

日期：2026-10-25。用户授权完成 PWA 安全更新闭环、旧版到新版升级验证、完整 Web 基线和文档同步，暂不推送或发布。

## 范围与结果

从 `dev` / `81c01e5` 的干净工作区和暂存区开始，本地 `origin/dev` 同指该提交；未 fetch。实现与文档保留为本地未提交修改，未推送、创建 PR、部署、打 tag 或发布 Release。

新版发现更新后提示用户，支持稍后处理；点击“保存并更新”后检查存储与进行中操作、检查其他窗口、保存最新文章、再次核对快照、激活 Worker 并等待实际接管，最后刷新。失败恢复交互、保留输入并提供仅文本导出。资源加载失败不再直接自动刷新。详细契约统一见 [PWA 安全更新](../development/pwa-updates.md)。

浏览器与目录仍复用现有文章保存、冲突保护和资源格式，没有更换数据库、schema、存储键、文章 ID 或目录句柄库。没有增加依赖、更新锁文件或修改真实用户文章。

## 主要修改

- Vite PWA 改为 `prompt`，禁用自动注入注册与自动接管。`src/pwa/` 管理发现、提示、保存、通信及超时；首次安装不误报为更新。
- Worker 激活守卫校验同作用域全部窗口与消息发起方，阻止其他标签页 / 已安装窗口存在时激活，拦截旧 `SKIP_WAITING` 旁路。该检查不是跨浏览器窗口生命周期的原子锁。
- 图片 / 文件操作、历史写入队列、目录包维护暴露内存中的忙碌状态；更新期间暂时禁止应用内容交互，保存与激活后均重新核对文章和工作区。
- 动态资源错误和应用错误边界的重新加载入口接入安全保存流程。启动阶段根错误边界仍单独处理。
- Nginx 模板为 `pwa-update-guard.js` 增加重新验证缓存策略；没有实际容器或线上部署。
- 添加固定生产构建、版本切换服务器及浏览器升级脚本，避免 HMR、清库、注销 Worker 或控制台强制激活造成虚假升级证据。

### 固定构建的浏览器升级

执行环境为 macOS 上独立 Playwright CLI 会话，Chrome `155.0.8059.86`；测试服务仅监听 `127.0.0.1:4183`。`legacy` 是实施前 `81c01e5` 的实际生产构建；`new` / `next` 是当前源码的两次真实 Vite / Workbox 构建，仅通过测试插件加入不同标记形成不同 JS hash 和预缓存清单，不冒充另一发布版本。

执行 `scripts/browser/pwa-upgrade-checks.js`，结果通过，页面运行错误为 0：

1. 在旧版导入含未知 frontmatter 的合成文章并插入图片。安装新版后旧页面没有新 UI；完成最新输入保存，关闭全部页面，观察 Worker 自然激活，重新打开新版。正文、元数据及图片原字节保留。
2. 从新版到后一测试构建：点击“稍后”不激活；另一同作用域页面含未保存输入时，当前页更新被阻止，另一页内容仍在。
3. 延迟真实图片解码时更新被阻止，释放后资源保存与正文插入完成；延迟真实 ZIP Worker 操作时更新被阻止，使用产品取消入口恢复。
4. 注入 IndexedDB 配额拒写：更新不激活、不刷新，输入保留且解除交互锁；恢复写入后，在离线状态完成保存、激活与重载。最新正文、未知 frontmatter 和两张 93 字节 PNG 均保留，图片字节逐项一致。

旧版迁入与新版后续更新是两类证据。历史页面无法被新代码补上提示，首次迁入需先保存、关闭全部站点窗口，再打开；普通刷新可能仍得到旧版。
